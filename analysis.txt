一、项目定位
--------------------------------------------------------------------------------
• 名称：chat-code-bridge（npm private，MIT）
• 目标：将飞书（Lark）与企业微信 IM 与本地 Cursor Agent CLI（可执行文件 agent）桥接，
  实现聊天驱动本地工作流。
• 运行时：Node.js >= 22；ES Module（package.json 中 "type": "module"）。
• 当前分支：feature/ts-version — 根入口为 main.ts；src 以 TypeScript 为主；
  仅 src/aiCode/cursor/ 仍为 JavaScript（未纳入 tsconfig 的 include，由 Node 直接加载）。


二、根目录与入口脚本
--------------------------------------------------------------------------------
main.ts          应用入口：若 ~/.chat-code-bridge/chat-code-bridge.json 为空，则交互选择
                 IM 类型、录入凭证、选择 AI 桥接（cursor）与当前项目，合并写入用户目录
                 JSON；随后 drawLogo()。当前未在入口中根据 bridge.key 启动飞书/企微监听。
tools.ts         开发辅助：spawn 本机 agent，以 stream-json / stream-partial-output
                 解析 stdout，在终端打印模型与工具调用进度（与 bash 流式脚本等价）。
package.json     脚本：
                 • npm run dev   → tsx watch main.ts
                 • npm run tools → tsx watch tools.ts
tsconfig.json    ES2022、strict、路径别名 @/* → ./src/*，@config/* → ./config/*；
                 include：main.ts、tools.ts、src/**/*.ts、config/**/*.ts
README.md        使用说明与数据流；目录树仍以 main.js / 旧 utils 布局描述为主（见第六节）。


三、依赖概览
--------------------------------------------------------------------------------
生产依赖：
  @larksuiteoapi/node-sdk   飞书/Lark OpenAPI 与 WS
  @wecom/aibot-node-sdk     企业微信智能机器人 WebSocket
  dayjs、lodash-es、uuid
开发依赖：tsx、typescript@6、@types/node、@types/lodash-es


四、配置层（config/）
--------------------------------------------------------------------------------
json/
  chat-code-bridge.template.json   桥接配置数组模板（uuid、appBridge、aiCodeBridge、
                                     currentProject、各 chatApp 凭证占位）
  project-config-list.template.json  项目 workspace 列表模板
  support-chat-app.json            可选 IM：feishu / lark / wecom 及 needConfigKeys
  support-ai-code-app.json         可选 AI 侧：目前仅 cursor
ts/
  file-path-enum.ts                FilePathEnum：仓库内模板路径与用户目录
                                   ~/.chat-code-bridge/ 下 JSON 文件名

路径解析（src/utils/fileEvents.ts 中 getFilePath）：
  • 键名以 USER_LOCAL_ 开头 → 前缀为用户主目录（os.homedir），再拼接枚举中的相对路径；
    例如 USER_LOCAL_CHAT_CODE_BRIDGE_CONFIG → ~/.chat-code-bridge/chat-code-bridge.json
  • 其余键 → 前缀为项目当前工作目录 process.cwd()

.gitignore：忽略 node_modules、package-lock.json、整个 config/ 目录。若 config 需纳入版本
  控制，应调整忽略规则或确认团队通过 git add -f 等方式管理模板文件。

六、与 README.md 的差异
--------------------------------------------------------------------------------
README「目录结构」仍描述 main.js、根目录 utils/*.js、src/chatApp/index.js、feishu/send-message/、
lark/ 再导出等；当前仓库为 TypeScript 主入口 main.ts，无上述旧版 JS 文件布局与 send-message
子目录。README「快速开始」中「与 main.js 一致」的分支启动说明（按 key 调用 start*Listener）
尚未在 main.ts 中实现；若需文档与代码一致，应更新 README 或在 main 中补全启动逻辑。


七、数据流（设计意图）
--------------------------------------------------------------------------------
1）首次运行：向导合并用户配置 → 选择 IM 与 Cursor 项目 workspace。
2）运行时（目标）：IM WebSocket 收消息 →（可选）Typing 等 → 调用 agent → 将输出写回会话。

当前 main.ts 仅完成首次向导与 Logo；飞书/企微监听需由其他入口或后续接入 main 串联。


八、风险与注意（结构层面）
--------------------------------------------------------------------------------
• src/chatApp/wecom/index.ts 中机器人凭证为硬编码，提交前需改为配置或环境变量，避免泄露。
• aiCode/cursor 与上层 TS 并存，注意统一构建/运行方式与类型边界。
• 用户目录 ~/.chat-code-bridge 含敏感凭证；确保不提交到仓库；留意 .gitignore 与 CI 缓存。
